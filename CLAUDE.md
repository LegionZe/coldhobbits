# CLAUDE.md

Foundry VTT system `ad2e` (AD&D 2nd Edition, mechanics only), targeting Foundry v14 (minimum build 14.368).
Code in this repository is generated with Claude Code; keep the notice in README.md and system.json.

## Release workflow (standing instruction from the repo owner)
Every change ships as a release. For each change, without asking again:
1. Bump `version` in `system.json` (patch increment unless told otherwise).
2. Commit on the working branch and push it.
3. Open a pull request to `main` (if the branch's previous PR was merged, open a new one).
4. Merge the pull request.
5. Confirm `.github/workflows/release.yml` succeeded and that
   https://github.com/LegionZe/coldhobbits/releases/latest/download/system.json serves the new version.
The owner installs and updates from that manifest URL only (no shell access to the Foundry server).

## Development notes
- Reference implementation for v14 APIs: https://github.com/foundryvtt/dnd5e. API docs: https://foundryvtt.com/api/.
- Core calls `Actor#getRollData()` during `applyActiveEffects()` (actor and token level), before `prepareDerivedData()`.
  Roll data must not depend on derived-only values.
- Before writing CSS or selectors, get the real rendered HTML from the owner or a diagnostic macro; do not guess.
- Ability tables: `module/rules/ability-tables.mjs` is GENERATED by `python3 tools/build-ability-tables.py`
  (MediaWiki API of adnd2e.fandom.com; the HTML pages return a Cloudflare challenge). Edit the generator, not the output.
- Level tables: `module/rules/level-tables.mjs` is GENERATED by `python3 tools/build-level-tables.py` (Table 60 saves,
  Tables 14/20/23/25 hit dice + XP, Table 53 THAC0, Table 15/35 attacks per round).
- Races: `packs/_source/races/*.json` and `module/rules/race-tables.mjs` (Table 9) are GENERATED by
  `python3 tools/build-race-data.py` (run after build-class-data.py; it reads Table 22 races from the class sources).
  Racial level limits (`LEVEL_LIMITS`) are the owner-supplied table; kit racial limits are curated in
  build-class-data.py `KIT_RACES` (run build-class-data.py, then build-race-data.py).
  Ability `value` = rolled score; derived `total` = value + racial adjustment; use `total` everywhere except Table 7 checks.
- Proficiencies: `packs/_source/proficiencies/*.json` and `module/rules/proficiency-tables.mjs` are GENERATED by
  `python3 tools/build-proficiency-data.py`, which also writes bonus/required proficiencies and bonus slots into the kit
  sources (curated exceptions in `KIT_OVERRIDES` / `KIT_SLOTS`; it fails on unresolved names); weapon data `system.weapon` comes from
  Weapon List (PHB) + Table 45, with `NO_DAMAGE` and `strength_use()` documenting exceptions. Bow items: `bowStrength`
  ("17", "18/50"...; `bowStrengthRow` in character.mjs) gives Strength bonuses up to the rating. It also writes
  `packs/_source/weapons` (weapon and ammunition Items; weapon `system.proficiency` = proficiency identifier).
- Movement: `module/rules/movement-tables.mjs` is GENERATED by `python3 tools/build-movement-tables.py` (Tables 47, 48,
  64, Table 42 coin values, DMG coin weight); build-race-data.py also reads Table 64 for race `move`.
- Armour: `packs/_source/armor/*.json` are GENERATED by `python3 tools/build-armor-data.py` (Armor List (PHB) +
  Table 46; it asserts Table 46's "+ shield" entries are one better than the armour alone). Run generators via
  `tools/build-all.sh` (order: ability, level, class, proficiency, movement, race, armor, equipment, spell, monster).
- Equipment: `packs/_source/equipment/*.json` (coin and equipment Items: Table 42 coins, Table 44 lists, Tables 49/50) are
  GENERATED by `python3 tools/build-equipment-data.py` (heading rows and their sub-items are curated in `SUBITEMS`;
  it asserts every Table 50 container exists).
  `module/migrations.mjs` moves 0.0.20 `system.currency` counts into coin items on `ready` (GM).
- Containers: `module/containers.mjs` (pure rules: `system.container` = container item id on the same actor; container =
  equipment/magic item with `capacity` weight, volume or `weightless`; `inventory()` gives carried/counts/contents for
  character and monster loads; links to a missing item, a loop, or from an equipped item are ignored; `containerPreUpdate`
  in the weapon/armour/magic data models' `_preUpdate`). Sheet side `module/sheets/containers-ui.mjs` and partial
  `ad2e.container-list`; item rows are `.draggable` with `data-item-id` (ActorSheetV2 drag selector, as dnd5e's rows),
  container blocks carry `data-container-id`. Magical containers are curated in build-magic-item-data.py `MAGIC_CONTAINERS`.
- Mounts / pack animals: `module/animals.mjs` (`loadBand` = PHB Table 49 bands, `isAnimal` (role mount/pack/pet or a
  Table 49 load), `riderWeight` = `system.bodyWeight` + rider's encumbrance total, `riderOf` via game.actors and
  character `system.animals.riding` (UUID); hooks re-prepare a rider's animals on actor/item changes and on ready).
  Monster derived `encumbrance` = { own, rider, weight, band, rate }. PHB Table 10 weights are `RACE_WEIGHT` in
  race-tables.mjs (build-race-data.py). Pack animals (role "pack") are `PACK` in build-hireling-data.py.
- Familiars: `module/familiars.mjs` (`findFamiliar` GM roll, `familiarDeath`, `familiarSurpriseBonus` used by
  rollSurprise, updateWorldTime hook for the daily loss when separated); character `system.familiar` { uuid, near,
  separated, deathResolved, lastAttempt }; monster role "familiar". `module/rules/familiar-tables.mjs` and the Familiars
  folder of packs/_source/hirelings are GENERATED by build-hireling-data.py (`FAMILIARS`, `FAMILIAR_RULES` regexes).
- Monsters: actor type `monster` (also hirelings, mounts, pets). `module/rules/monster-tables.mjs` (DMG Table 39) and
  `packs/_source/monsters/*.json` (prototype actors with embedded items, `_key` `!actors.items!<actor>.<item>`) are
  GENERATED by `python3 tools/build-monster-data.py` (runs last; copies items from the weapon/armour/equipment sources).
- Hirelings & Mounts: `packs/_source/hirelings/*.json` (monster actors; DMG Table 64 soldiers with the equipment their
  descriptions name, checked by regex in `SOLDIERS`; DMG Table 65 civilians; Horse/Camel/Elephant mounts with PHB load and
  price; stats from Human (MM) columns) are GENERATED by `python3 tools/build-hireling-data.py` (after build-monster-data.py).
  Monster `system.cost` holds the wage or price.
- Magical items / treasure: item types `magic` and `jewellery`; `module/rules/treasure-tables.mjs` (DMG Tables 85, 87,
  88) is GENERATED by `python3 tools/build-treasure-tables.py`. Situational roll modifiers: `module/roll-modifiers.mjs`
  (modifier + reason fields used by every roll dialog and `AD2ECombat#rollInitiative`). `packs/_source/magic-items`
  (DMG Tables 89-104: name, category, XP value, usable-by groups, charges for wands/rods/staves whose page mentions
  them, link) and `packs/_source/gems` (DMG gem lists by Table 85 class) are GENERATED by
  `python3 tools/build-magic-item-data.py` (after build-treasure-tables.py). No item descriptions are copied.
- Al-Qadim equipment: `packs/_source/aq-equipment` (pack "Al-Qadim Equipment (AA)") is GENERATED by
  `python3 tools/build-aq-equipment-data.py` (after build-proficiency-data.py and build-armor-data.py): "Equipment
  Lists (AA)" at the N (normal) price, pp/pg scanning errors read as gp, new weapons + proficiencies, lamellar, daraq.
  File names carry the item type (a weapon and its proficiency share an identifier).
  It also writes the "PHB Weapons (Zakharan prices)" folder (`AA_WEAPONS` maps AA rows to PHB items; others x10) and
  `module/rules/aq-tables.mjs` (heat penalty, asserted against Table 6), used by `module/aq-rules.mjs` (world setting
  `aqArmorHeat`, `system.mods.heat` on attacks and checks). Kit field `xpTable` (Kahin: druid, `KIT_XP` in
  build-class-data.py, asserted against the Table 3 footnote); corsair two-weapon exemption in combat-tables.
- Hit points and death: `module/health.mjs` (rules, death-rule setting, status icon sync on updateActor, bleeding per
  round on updateCombat by the active GM, chat context menu on messages flagged `flags.ad2e.damage`), actor methods
  applyDamage / applyHealing / bindWounds / restHeal / raiseFromDead / recoverTemporary; derived `system.hpState`.
  Temporary damage: `hp.punch` (75% returns on deleteCombat) and `hp.temp` + `hp.tempUntil` (returns on updateWorldTime,
  one turn after the combat); chat flags `damageKind` ("punch" | "nonlethal") and `temp`.
  Targets: attack/damage messages carry `flags.ad2e.targets` ([{ uuid, name }] from `game.user.targets` at roll time;
  damage falls back to the last attack's targets per actor and weapon/attack key); the context menu resolves them with
  `foundry.utils.fromUuidSync(uuid, { strict: false })`.
  Buttons: `module/documents/chat-message.mjs` (CONFIG.ChatMessage.documentClass) overrides `renderHTML` like dnd5e's
  ChatMessage5e and calls `damageButtons` (GM only); buttons and context menu share `applyFromMessage`.
- Sheet partials: `templates/actor/parts/{weapon-list,armor-list,class-abilities}.hbs`, registered by name in init with
  `foundry.applications.handlebars.loadTemplates({ "ad2e.<name>": path })` (as dnd5e); used by the Equipment, Class
  Abilities and Combat tabs. Hash parameters are not visible inside nested `{{#each}}` blocks: re-bind them with
  `{{#with x as |x|}}` (class-abilities does).
  A sheet is one form: an input name may appear only once across all tabs (a duplicate makes the form submit an array
  and every update fails validation, e.g. "ac: misc: must be a number" in 0.0.51-0.0.52). The Combat tab passes
  `combat=true` / `ft.combat` so the partials show those values as text.
- Opaque windows: `module/opaque-windows.mjs` makes the computed window background of `.ad2e` applications fully opaque
  (renderApplicationV2 hook; client setting). Diagnosed on core 14.368: `form.application.sheet.ad2e` background
  rgba(11, 10, 19, 0.9) with backdrop-filter none under `body.performance-low`.
- Sidebar tab colours: `module/sidebar-colours.mjs` (client setting `sidebarTabColours`, body class `ad2e-tab-colours`;
  CSS in styles/ad2e.css). Diagnosed on core 14.368: `menu > li > button.ui-control[data-action="tab"][data-group="primary"]
  [data-tab="combat"]`, the icon is the button's own glyph, the open tab has `.active` / `aria-pressed="true"`.
- Surprise: `module/rules/encounter-tables.mjs` (DMG Table 57) is GENERATED by `python3 tools/build-encounter-tables.py`;
  `AD2EActor#rollSurprise`. Encounter reactions: Table 59 in the same file, `module/reaction.mjs` (`rollEncounterReaction`,
  monster sheet button, `game.ad2e.rollReaction()`; speaker's Charisma + kit reaction modifiers subtracted). Morale Tables 49/50
  (same file) and henchmen: `module/henchmen.mjs` (`system.henchmen` { actors: UUIDs, lost }, drop via
  `CharacterSheet#_onDropActor`, Bio tab). Experience: `AD2EActor#awardExperience` (individual) and `module/apps/award-xp.mjs`
  (group award, settings menu + `game.ad2e.awardExperience()`).
- Two weapons / unarmed: `module/rules/combat-tables.mjs` (PHB Tables 57/58, two-weapon penalties, overbearing,
  non-lethal weapon attacks) is GENERATED by `python3 tools/build-combat-tables.py`; pure rules in
  `module/combat-options.mjs`; `AD2EActor#rollUnarmed` (characters and monsters), two-weapon, non-lethal and armed-defender
  (+4 vs an unarmed attacker, `vsUnarmed`) options in rollWeaponAttack/Damage and rollMonsterAttack/Damage.
  PHB Table 51 (`COMBAT_TABLES.combatModifiers`, `STATUS_51` in the generator maps core status ids from the owner's
  diagnostic: sleep/paralysis/restrain/unconscious = automatic hit, stun/prone +4, invisible -4) in every attack dialog.
  Automatic damage on a hit (client setting `autoDamage`): rollWeaponDamage / rollMonsterDamage take a `preset` (no dialog).
  Character size (`system.sizeCategory`, derived) comes from `RACE_SIZE` in race-tables.mjs (build-race-data.py, Monstrous
  Manual sizes asserted by regex); `needsTwoHands` / `twoWeaponRate` give two-handed weapons and the extra-attack rate.
- Initiative: `module/initiative.mjs` (Tables 55/56 from combat-tables.mjs: weapon speed, casting time, items, size;
  automatic action = last attack's weapon (`actor._ad2eLastWeapon`, set in rollWeaponAttack) or fastest in hand);
  `AD2ECombatant#getInitiativeRoll` (Roll All, as dnd5e's Combatant5e) and the `AD2ECombat#rollInitiative` dialog.
  World setting `initiativeMode` (individual | group | standard): side = token disposition, one 1d10 per side and round
  stored in combat flag `ad2e.sides.r<round>` (GM rolls it); scrolls ask for the spell's casting time; casting drops Hasted.
- Ability score generation: `module/ability-methods.mjs` (pure rules for PHB Methods II-VI) and
  `module/apps/ability-roller.mjs` (dialog from the Abilities panel; writes `system.abilities.<key>.value`).
- Monster importer: `module/importers/complete-compendium.mjs` (pure parsing: /catalog/ HTML, page-data JSON) and
  `module/apps/monster-importer.mjs` (ApplicationV2, settings menu + `game.ad2e.importMonsters()`). Fetches run in the
  GM's browser (the site sends `access-control-allow-origin: *`). Import stat blocks and links only, never `fullBody`.
  Pictures: `monster_data.images` (`img/x` -> /images/monsters/img/x, `/img/spc/x` from the root, `grf/` = logos), linked
  as actor `img` and `prototypeToken.texture.src` after a HEAD check (the site links some missing files).
- Spells: `module/importers/adnd2e-wiki.mjs` (shared infobox parser; MediaWiki API with `origin=*`) used by
  `module/apps/spell-importer.mjs` and by `tools/build-spell-data.py` (via `tools/spell-items.mjs`), which also GENERATES
  `module/rules/spell-tables.mjs` (Tables 21, 24, 17, 32) and the example spells in `packs/_source/spells`.
  Learning wizard spells: `module/learn-spells.mjs` (`learnChance`, `rollLearnSpell`; spell fields `learned`,
  `learnFailedLevel`; world setting `maxSpellsPerLevel`; drop prompt in CharacterSheet#_onDropItem).
- Class abilities: `module/rules/class-tables.mjs` is GENERATED by `python3 tools/build-class-ability-tables.py`
  (Tables 18, 26-30, 33, 61); thief/bard/ranger skills, backstab, turning undead and paladin abilities are derived in
  `CharacterData#computeClassAbilities` (a skill below 1% after adjustments is `belowOne` and not usable, Thief (PHB)).
  class-tables.mjs also holds `classArmor` (CLASS_ARMOR in the generator, asserted against Wizard/Thief/Bard/Druid (PHB));
  `armorRestriction`, `armorFits`, `armorWeightFactor` in character.mjs; armour item `size` ("" = made for its wearer).
- Kit mechanics: `tools/build-kit-mechanics.py` (run after build-proficiency-data.py) writes `modifiers`, `skillAdjust`
  and `skillPoints` into the kit sources from the curated `KIT_MODIFIERS` / `KIT_SKILLS` / `KIT_POINTS`; each entry has
  a `match` regex that must occur in the current kit page (the script fails otherwise). Conditions are paraphrased.
  Unconditional modifiers apply in `CharacterData#computeKitModifiers`; conditional ones are tick boxes in roll dialogs.
  It also writes kit `specialization` ({ mode: "" | allowed | required | forbidden, free: [weapon proficiency ids] }) from
  `KIT_SPECIALIZATION`; `CharacterData#computeProficiencies` applies it. Kit `recommendedProficiencies` (identifiers) are
  written by build-proficiency-data.py `kit_recommended` (linked or exactly named proficiencies only; never guessed).
- Classes/kits are Items (`class`, `kit`). `packs/_source/{classes,kits}/*.json` are GENERATED by
  `python3 tools/build-class-data.py` (kit ability minimums are curated in its `KIT_REQ`; the script fails if the wiki
  and `KIT_REQ` disagree). Al-Qadim kits (categories "Character Kit AA" / "Character Kit CShaH"): classes from
  "Kits (AA)" Table 3, requirements curated in `AQ_REQ` with a regex checked against each kit page. LevelDB packs are compiled by `npm run build:packs` (@foundryvtt/foundryvtt-cli, as dnd5e)
  in the release workflow; compiled packs are git-ignored.
  `system.json` `packFolders` puts every compendium in one "AD&D 2nd Edition" folder (as dnd5e's manifest); add each new
  pack name there too.
- A `StringField` with `choices` defaults to `blank: false` and `nullable: false` (Foundry StringField docs: "If this field
  is created with `choices`, the default changes to `false`"); a choice field that may be empty needs `blank: true`, or
  Foundry drops invalid values on load (0.0.31-0.0.38 lost kit modifiers this way). The Node tests stub fields and
  cannot catch this; `node tools/check-pack-data.mjs` (run by the release workflow) checks every pack document.
- Test template rendering with helpers that behave like Foundry's (e.g. `selectOptions` throws on null choices).
- THAC0 uses PHB Table 53 (generated); the progression in config.mjs only extends it past level 20 and is asserted
  against Table 53 by build-level-tables.py. Do not include rulebook text.
